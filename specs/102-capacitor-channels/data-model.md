# Data Model: Native Release Channels

No on-chain entities, no gateway state, nothing joins the member backup. The
feature's data is build-time configuration and release-record rows.

## Tenant native identity (`tenants/<id>/manifest.json` → `native` block)

```jsonc
{
  "native": {
    "ios":     { "appId": "app.fairwins.ios" },      // bundle identifier
    "android": { "appId": "app.fairwins.android" },  // application id
    "displayName": "FairWins",                        // home-screen name
    "iconSource": "icons/native/"                     // masters the shells' icon sets are generated from
  }
}
```

- One tenant → one `appId` per platform (spec FR-007); distinct across tenants
  so two tenants install side by side (Story 6).
- Absent `native` block ⇒ tenant has no native channel; the native build fails
  loudly naming the tenant, never borrowing another tenant's identity.
- Validated by `npm run tenants:validate` (schema extension), including
  cross-tenant `appId` uniqueness.
- The associated-domains identity (passkey RP + deep links) is the tenant's
  existing origin from the manifest — not a new field; the association FILES
  (AASA, assetlinks) are served by the tenant origin and carry the platform
  `appId`s above plus operator-held team/signing ids (documented in the
  runbook, never in the manifest).

## Generated native config (never hand-edited)

- `frontend/capacitor.config.ts` — generated by
  `scripts/native/sync-native-config.js` from tenant manifest + cohort +
  `scripts/release/version.js`. Committed for the default tenant so the shells
  build reproducibly; regenerated (and diff-gated) at build.
- Native version fields — `versionName`/`versionCode` (Android),
  `CFBundleShortVersionString`/`CFBundleVersion` (iOS): written from
  `version.js` only. `versionCode`/`CFBundleVersion` derive monotonically from
  the semver (`major*10^6 + minor*10^3 + patch`), so one version source yields
  one build number. `check-native-versions.js` is the regenerate-and-diff gate.

## Release-record artifact rows (spec-076 record PR)

Each release tag's record gains, per native channel:

| field | meaning |
|---|---|
| `channel` | `ios` \| `android` \| `web` |
| `artifact` | file name (`FairWins-<version>.aab`, `FairWins-<version>.xcarchive.zip`, web bundle) |
| `sha256` | digest of the artifact bytes as built in CI |
| `signed` | `true` (Android, upload key) \| `false` (iOS CI export — signing is the operator ceremony) |

A row exists only for an artifact that was built AND its smoke job passed
(FR-009); a missing row is a failed release, never an omission.

## Runtime states (frontend seams)

- **Runtime**: `web` | `native-ios` | `native-android` — resolved once by
  `lib/native/runtime.js`; every native-conditional surface reads this seam,
  never a user-agent sniff.
- **Native capability**: per capability (`passkey-ceremony`, `ble`,
  `deep-links`) resolves `available` | `unavailable(reason)` — a three-state
  honest read in the estate tradition: `unavailable` always carries the
  member-renderable reason (OS floor, permission denied, radio off,
  Play-services gap) and is never collapsed to a silent hide.
- **Lifecycle**: `active` → `background` → (`active` | process death). The
  adapter emits the same hide/show events the app-lock policy consumes; state
  transitions and their lock consequences live in the existing policy,
  untouched.
- **Pending deep link**: a URL captured at `appUrlOpen` while the gate
  (sign-in or lock) is up; consumed exactly once after the gate clears;
  dropped only on explicit sign-out, never silently.
